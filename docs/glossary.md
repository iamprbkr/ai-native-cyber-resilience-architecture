# Glossary

| Term | Definition |
|------|------------|
| **Alert** | A normalized security event from any source (SIEM, EDR, etc.) |
| **Asset Criticality** | Business importance rating (low/medium/high) assigned to each asset |
| **BCP** | Business Continuity Plan — ensures critical functions during disruption |
| **C4 Model** | A hierarchical approach to visualizing software architecture (Context, Container, Component, Code) |
| **CTI** | Cyber Threat Intelligence — contextual information about threats |
| **D3FEND** | MITRE's defensive ATT&CK framework mapping countermeasures to threats |
| **EDR** | Endpoint Detection and Response — endpoint security monitoring |
| **Enrichment** | The process of adding contextual information to a raw alert |
| **GRC** | Governance, Risk, and Compliance |
| **Incident** | A group of related alerts that constitute a security event |
| **IOC** | Indicator of Compromise — evidence of a security breach (IP, domain, hash) |
| **IR** | Incident Response |
| **LLM** | Large Language Model — AI model used for natural language understanding |
| **MITRE ATT&CK** | A globally-accessible knowledge base of adversary tactics and techniques |
| **MTTD** | Mean Time to Detect |
| **MTTR** | Mean Time to Recover (or Respond) |
| **NIST CSF** | National Institute of Standards and Technology Cybersecurity Framework |
| **PEP** | Policy Enforcement Point — a control point in Zero Trust architecture |
| **Playbook** | A structured, repeatable set of actions for handling a specific incident type |
| **RBAC** | Role-Based Access Control |
| **RTO/RPO** | Recovery Time Objective / Recovery Point Objective |
| **SAST** | Static Application Security Testing |
| **SBOM** | Software Bill of Materials — inventory of software components |
| **Severity** | The technical impact level of an alert (info/low/medium/high/critical) |
| **SIEM** | Security Information and Event Management |
| **SOAR** | Security Orchestration, Automation, and Response |
| **SOC** | Security Operations Center |
| **STRIDE** | Microsoft threat modeling methodology (Spoofing, Tampering, Repudiation, Information Disclosure, Denial of Service, Elevation of Privilege) |
| **Zero Trust** | NIST SP 800-207 security model: never trust, always verify |
